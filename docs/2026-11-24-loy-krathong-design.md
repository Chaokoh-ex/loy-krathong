# เว็บลอยกระทง TCC 2569 — Design

## เป้าหมาย / ทำไม
กิจกรรมสนุกในบริษัท พนักงานประมาณ 200 คนลอยกระทงออนไลน์ร่วมกันในคืนวันลอยกระทง (อังคาร 24 พ.ย. 2569) ใช้งานคืนนี้

## สิ่งที่ผู้ใช้ทำ
1. สแกน QR → เข้าเว็บ (ไม่ต้องล็อกอิน)
2. เลือกกระทง 1 แบบ (ใบตอง, ดอกบัว, ขนมปัง, กะลามะพร้าว ฯลฯ)
3. ใส่ชื่อ (ชื่อเล่นได้) + เขียนคำอธิษฐาน ≤ 100 ตัวอักษร
4. กดลอย → กระทงลอยในแม่น้ำรวมที่ทุกคนเห็น แตะกระทงใดก็อ่านคำอธิษฐานได้

## Goals
- แม่น้ำรวม กระทงใหม่ค่อย ๆ ลอยเข้ามา (ดึงข้อมูลทุก 3–4 วินาที)
- กระทงของตัวเองมีแสงเรือง + ป้าย "ของฉัน"
- ฉากกลางคืน: พระจันทร์เต็มดวง, ตึก TCC วาดจากรูปจริง (ระเบียงโค้งคลื่นสีไม้, กระจก, เสาขาว, หลังคาทางเข้า, ต้นไม้ใหญ่) เปิดไฟอุ่น, ต้นมะพร้าวริมน้ำ
- บิลบอร์ด: สลับรูปสินค้า 6 ตัวจาก tcc-chaokoh.com (กะทิกระป๋อง, น้ำมะพร้าว UHT, น้ำมันมะพร้าว, น้ำพริกแกงเผ็ด, น้ำจิ้มไก่, วุ้นมะพร้าว) + แถบโลโก้ TCC, ชาวเกาะ, แม่พลอย, ยอดดอย
- ตัวนับจำนวนกระทง
- 1 เครื่อง ลอยได้ 1 ใบ (localStorage)
- ซ่อนกระทงไม่เหมาะสม: ติ๊ก `hidden` ในหน้า Supabase
- โปสเตอร์ QR
- พลุขึ้นบนจอของคนที่กดลอยทันทีที่กด (ตัดสินใจโดยผู้ใช้)

## ถ้าทัน
- พลุเล็ก ๆ บนจอคนอื่นเมื่อมีกระทงใหม่เข้ามา
- โหมดจอใหญ่ (`?screen=1` ซ่อนปุ่ม/ฟอร์ม)

## Non-goals
แนบรูป, ล็อกอิน, แผนก/อันดับแผนก, หน้าแอดมินแยก, เพลง/เสียงทุกชนิด (ผู้ใช้ตัดออก)

## Anti-goals
เว็บล่มหรือค้างกลางงาน, ข้อความไม่เหมาะสมค้างบนจอ, ฉากรกจนอ่านคำอธิษฐานไม่ได้

## Approaches
- **A. Supabase + GitHub Pages (เลือก)** — stack เดิมที่ผู้ใช้คุ้น, รับ 200 คนได้ด้วยการ poll แทน realtime (free tier realtime จำกัด ~200 connection)
- B. Google Sheet + Apps Script — ช้า ติดโควตา เสี่ยงค้าง
- C. Claude artifact — พนักงานส่วนใหญ่ไม่มีบัญชี เข้าไม่ได้

## Data
ตาราง `krathongs`: id, created_at, name, wish, style, hidden(bool, default false)
RLS: anon insert ได้ (ตรวจความยาว), anon select เฉพาะ hidden = false; ไม่มี update/delete จาก anon

## ส่วนที่ปล่อยให้ผู้สร้างตัดสินใจ
ลายกระทงแต่ละแบบ, ฟอนต์ไทย, การจัดตำแหน่งกระทงไม่ให้ทับกัน, รูปสินค้า/โลโก้คัดลอกมาเก็บใน repo
